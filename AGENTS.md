# AGENTS.md

## Hard rules
- **Never shadow real git command**: passthrough is whole premise, so enhanced view always gets distinct verb (`trace`, not `log`; `i` prefix for interactive: `irepos`/`ilog`/`ibranch`/`itag`/`iremote`/`istatus`/`istash`/`iscan`).
- Scratch/test git repos go in `playground/` (gitignored). Build them there and **leave them**: user opens them to test TUIs by hand.
- **Never take README screenshot or record GIF by hand.** Every file in `readme-assets/` rendered by VHS from `demo/` against six invented repos `demo/stage.sh` builds and deletes. New asset means new tape or new `Screenshot` line, never terminal and crop. No rig directory name reaches a frame.
- **Each README section is interactive tool plus plain twin, answered from same fixture** (`iscan`/`search`/`scan`, `irepos`/`repos`, `ilog`/`trace`, `istatus`/`status`, `istash`/`stash list`, `ibranch`/`tidy`, `itag`/`tag`, `iremote`/`branch -vv`), because that pairing is what sluuz *is*. One tape per feature GIF; plain stills (`<feature>-plain.png`) all come from `plain.tape`, whose own GIF is recorded into stage and deleted with it. VHS does not redraw while hidden, so `Screenshot` cannot be taken off-camera inside feature tape. Only still of a tool: `ilog-diff.png`, taken by `Screenshot` line inside clip that already covers it.

## Invariants and gotchas
- **When editing TUI keys: plain = top pane, Ctrl = pane below.**
  - `Ctrl-j/k`≡`Ctrl-↑/↓` move pane below (on diff: scroll), `Ctrl-h/l`≡`Ctrl-←/→` pan.
  - No paging keys: held key speeds up through the one `Accel` in `tui/input.rs` every view asks how far a press goes, so new view never hardcodes step.
  - Each filter shown on its own pane's title with key that opened it (`Query::title_span`), so query never looks sent to other box.
  - Every typed text (both filters, `iscan`'s bar, typed gate's field, `Form` field) goes through `Query::on_key` in `tui/widgets.rs`; never edit text in a view's own key match.
  - Scope slider drawn as tabs on its pane's border (`scope_tabs` in `tui/widgets.rs`), never as one word for current stop.
  - Footer built by `key_footer` from `actions` in `app/ui.rs`; shared words are consts in `tui/widgets.rs` (`CREATE`, `EDIT`, `DEL`, `FIND`, `REFRESH`, `QUIT`, `HELP`, `FILTER_KEYS`, `GATE_KEYS`, `READER_KEYS`; `typed_popup` writes `↵ <verb> · esc cancel`), help motions are `Y_MOVE`/`CTRL_Y_MOVE`/`X_MOVE`/`CTRL_X_MOVE` in `tui/input.rs`; never hand-write shared key hint. Key only one screen has is plain verb (`s sync`, `t track`).
  - `?` help built by `help` in `app/ui.rs` (`HelpSection` rows in `Modal::help`), listing only levels reachable from entry level.
  - `:` opens `CommandLine` in footer (empty line runs `help`, `:q` quits).
  - Every box drawn inside panes above footer (`Modal::draw`, `confirm_popup`, `typed_popup` take that area). Footer doubles as 3-second status line (`NOTE`).
  - Pane border says what pane is, how far through it you are, and `/ find` or `ctrl-f find`, where filter shows once typed.
  - `r` re-reads current level from git, cursor kept on same item by name, since refresh is exactly when positions shift.
  - On diff, `r` waits (`Reopen`, `settle_reopen` in `app/diff.rs`) for *that* commit to stream back and its files to load before reopening same file at same scroll. Never lean on `fsel.restore` for it: while long log streams cursor sits on row 0, whose files often hold same path and would consume restore there.
  - `K` opens reader about row under cursor (`app/inspect.rs`, one arm per level; `inspect` in `istatus.rs`); reader wraps long value back to box's left edge, not under its column, so anything long (subject, message) goes in free text under rows (`Modal::with_text`), never in a row.
  - `Enter` on diff runs user's `git difftool`.
- **When parsing git output where leading whitespace matters** (notably `git status --porcelain`, whose first column is space for unstaged files): use `git_capture_raw`, not `git_capture`, which `.trim()`s, eating first record's leading space ("Cargo.lock" → "argo.lock").
- **When running git against paths it reported** (`git status --porcelain`, `git show --name-status`): anchor at repo root (`git rev-parse --show-toplevel`), since git reports paths root-relative and `diff`/`add`/`show -- <path>` from subdirectory silently mis-resolves. Every view resolves root once and passes it down: **no view calls `set_current_dir`**, and every loader in `git/load.rs` takes repo as first argument, which lets `irepos` walk several repos in one session.
- **When TUI talks to remote** (fetch, push, `ls-remote`): go through `unattended_git` in `git/load.rs`. Prompt would be typed into screen not reading it, and ssh asks on `/dev/tty`, not stdin, so `GIT_TERMINAL_PROMPT=0` alone does not stop it; remote that wanted prompt reads as unreachable.
- **When reading remote's tags:** git keeps no copy by default, so `itag` asks with `ls-remote` unless repo has `tag_rule` (`+refs/tags/*:refs/remote-tags/<remote>/*`, added by `t` on user's yes); then git's own copy drawn at once, refreshed with tags-only fetch. Keep that copy outside `refs/remotes/`: under it every tag lists as remote branch in `git branch -r` (and `ibranch`), and branch `tags/x` lands on same ref as tag `x`. Never cache answer anywhere git does not maintain it: copy only `itag` updates goes stale on user's own `git push --tags`.
- **When TUI shells out to interactive program** (e.g. `git difftool`): run it through `tui::suspended` so Ctrl-C ends child, not app. Check `diff.tool`/`merge.tool` *first*, so unconfigured user gets message, not torn-down screen (`run_difftool` in `tui/difftool.rs`). Exception: `istatus`'s `c` runs `git commit` with screen still up, so Ctrl-C at signing key's pinentry stays a key; `submit_commit` sets screen up again afterwards.
- **When TUI takes or gives back terminal:** `tui::init`/`tui::restore`, never ratatui's own. They start every `init` from terminal mode first `init` found and hand that back, since crossterm saves whatever mode it finds: difftool leaving echo off would otherwise reach shell. On Windows they also keep console input mode TUI's own: child ended by Ctrl-C leaves VT input on, or writes its mode back after TUI retook console, and under either crossterm misreads keys or Ctrl-C ends app.
- **When box shows what git said:** cut it with `git_words` in `git.rs`, never by hand.
- **When handling `Esc`:** call `norm_esc()` in `tui/input.rs` on every key event; kitty protocol we push makes `Ctrl-[` distinct key, so without it vim users lose `Ctrl-[`.
- **When diff pane shows hunk starting mid-file, highlighter needs lines above it**: `prepare_diff` takes `DiffContext` and primes itself at each `@@`; new diff caller hands it one (`commit_diff_ctx` in `git/load.rs` for commit, `blobs_for` in `istatus.rs` for index/worktree pair) or its diffs are stained.
- **When diff view feels laggy:** highlight ONCE with `prepare_diff` (syntect is expensive part), then `render_prepared` per scroll/pan. Never re-highlight on keypress.
- **When deciding which branches are safe to delete** (`tidy`, and `d` in `ibranch`): use "upstream gone" (`%(upstream:track)` contains `[gone]`), never `git branch --merged`, which wrongly lists `main` and release branches still alive on remote. Gone only signals branch finished, not proof its work reached remote, so both then ask `load::landed` (or find no commit of its own): `tidy` offers only those, with `git branch -D` because `-d` refuses anything squash- or rebase-merged, and lists rest apart.
- **When `d` deletes something** (`app/delete.rs`), box is decided by who loses what. Yes/No gate (opens on No) for what is finished or cheap to recreate: branch whose upstream is gone, tag no remote has (every tag, when no remote), remote (`git remote remove` drops only this clone's config and tracking refs; `c` with same URL brings them back). Branch whose commits no remote has (`unique_commits`) still gets plain gate when `landed` shows its changes already in remote's trunk, which is how squash or rebase merge leaves finished branch; counting commits cannot tell, since those merges give same changes new ids. Every delete from this clone records ref's old object (and branch's upstream config, which `git branch -D` drops) so `u` puts it back exactly. Typed gate (`typed_popup`) for what cannot be taken back and that others depend on or exists nowhere else: branch holding unlanded changes, branch or tag on remote (`push_delete`, run after frame that says so, like `s`), pushed tag, deleted on remote *and* here since deleting only here lasts until next fetch. Everything else is refused with `Modal` saying why, never silent no-op: `main`, `master` or remote's default branch (`is_trunk`, here or on remote, whatever state), checked-out branch, branch still alive on its remote.
- **When reading branch name to feed `git branch -d`:** take `%(refname)` and strip `refs/heads/`. `%(refname:short)` returns `heads/v1.2.3` when tag shares name, which `git branch -d` rejects.
- **When log is local branch's** (`ilog`'s HEAD, or branch at branches level whose row reads behind): `log_branch` names it and walk takes its upstream along, so what pull would bring in is on screen (`CommitMark::Incoming`, `Batch::Incoming`). `with_upstream` in `git/load.rs` builds walk for both `stream_commits` and `first_commit`, so emptiness check `ilog` runs before screen opens sees same commits. Branch at branches level asks only when row reads behind, since asking costs two more git calls per branch cursor rests on.
- **When adding command, `slu --help` groups it by `i` prefix.** Command list rendered by `help_template` in `main.rs`, not clap, which cannot give one subcommand different heading from another: name starting with `i` goes in interactive group, everything else in plain one. `Cmd` enum laid out in the two blocks it prints in. *Plain* command starting with `i` would be grouped wrong: another reason never to name one so.
- **When adding level to drill** (`Repos` → `Branches` → `Commits` → `Diff`, `Tags` standing where `Branches` would, `Remotes` where `Repos` would): ONE app in `src/app/`, not one per command; file list is preview pane at `Commits`, not a level. Add the `Level`, its scope slider, its `enter_*` loader, an arm in `app/keys.rs` and one in `app/ui.rs`. `irepos`/`ibranch`/`itag`/`iremote`/`ilog`/`istash` are small commands that only pick start level, and `Esc` quits at that level (`App::back`). `Tags` is only ever start level, so `Level::back` takes start to know tag's commits step back to it, and `request_commits` reads same start to walk tag's own range instead of `log_args` as plain log. `Remotes` is start level same way: under it branch list is branches of remote under cursor (`branch_remote`, read by `shows` in `app/branches.rs`), already loaded, so moving between remotes runs no git; remote branch's push state is local branch tracking it. `p` pushes checked-out branch with `-u` only when it tracks nothing (`load::push_branch`), because pushing fork's branch to `upstream` must not move where it pulls from. `istash` needs no level of its own: enters at `Commits` with `stashes` set and `log_args` walking stash reflog, because stash is merge commit whose first parent is HEAD it was made on, exactly what files pane and diff already read merge against. Rows named `stash@{n}` by position; `a`/`p`/`d` check that name still resolves to row's hash before acting, since stash made elsewhere shifts every number, and `d` carries name *and* hash into `Target::Stash` when box opens, since rows still streaming can move cursor while typed gate is up.
- **When level's bottom pane previews next level down: never load it on keypress.** Cursor move only sets `App::pending`; load asked for once input queue drains (`event::poll(ZERO)` in `App::event_loop`), so held `j` scrolls at terminal speed, not one `git log` per row. Load itself is thread streaming rows in batches (`stream_rows` in `git/load.rs`) that drawing loop drains a frame at a time; request cursor has moved past is cancelled mid-walk through shared `Feed::latest` counter. On repo whose git calls cost 300ms (Windows drive over WSL's 9p bridge), doing any of it synchronously makes `ibranch` unusable. Level *below* preview still loads only on `Enter`.
- **When job touches every repo in tree:** anything opening a connection per repo runs inside `with_remote_limit` in `git.rs` (`slu sync`, `tidy --prune`, `s`/`S` on Repos), because repos in tree usually share server and sshd's default `MaxStartups 10:30:100` resets connections past 10 logins in progress, reading as `kex_exchange_identification: read: Connection reset by peer` on random few repos. `each` runs whatever it is given, uncapped. On Repos level `s`, `S` and `r` run off input thread as one `RepoJob`; `take_scan` restores cursor from where it is when read lands, and asks for pane below only if app still on Repos; failure goes through `held_alert`. `s` on one repo (`sync`, `sync_remote`) is one fetch, still run after frame that says so. `tui/boot.rs` draws wait rows for `irepos` only.
- **When behavior doesn't match code you just wrote:** debug binary is stale. `cargo clean -p sluuz`, then rebuild. Usual cause: `cargo publish` (dry run included), whose verify build shares normal one's fingerprint and leaves it pointing at copy in `target/package/`, so cargo reports `Fresh` however much `src/` changes.
- `slu completions` delegates to git's own completion (only way branch names complete). git's completion is **lazy-loaded** and completing `slu` never trips that loader, so emitted script force-loads it.
- VS Code's integrated terminal cannot tell `Ctrl-J` from `Enter` on any OS (not just Windows). Fix is user `keybindings.json` remap to `Ctrl-Down`; no code-side fix.

## Build / lint / test
- `cargo build --release`, binary at `target/release/slu`.
- Run debug binary directly as `./target/debug/slu <cmd>`.
- No test renders a frame: TUI tests drive `App` state against throwaway repos; rest is pure logic.
- `cd demo && ./render.sh` re-renders every README asset in container, so machine needs only podman or docker. Image is `demo/Dockerfile`: vhs's own image pinned by digest plus git and less (pager git opens for plain stills), from `snapshot.debian.org` at date in its `SNAPSHOT` arg. Every tape runs in that one container, which stages once, so commit hashes and relative dates match across clips; runs as your user (`--userns=keep-id`, or docker's `--user`) so images stay yours and prompt ends in `$`, with no network since every remote is bare repo in stage. Container clock is UTC, so frame times are UTC on every machine. `./render.sh <tape>` does one of `plain` / `sleuth` / `repos` / `history` / `status` / `stash` / `tags` / `branches` / `remote` against freshly staged world. `./stage.sh up` then `./stage.sh shell` drops you in that world by hand (also fastest way to try TUI against interesting fixtures); `./stage.sh down` deletes it.

## Overview
`sluuz`: Rust CLI on crates.io, a **git superset**. Crate `sluuz`, binary `slu` (3-letter stand-in for `git`), AGPL-3.0-only. Anything git understands passes straight through to real git; on top, `slu` adds cross-repo management, history/secret search, prettier log, interactive TUIs.
Targets Linux and Windows alike (README also lists macOS), so code under `#[cfg(unix)]` needs Windows path beside it and `cargo check --target x86_64-pc-windows-gnu` must pass.
Layout:
- `src/main.rs`: `split_leading` takes git's options before the command off the line before clap sees it: `-C` is startup `set_current_dir` (never also forwarded, or relative path applies twice); rest go to git as typed and are refused in front of slu's own verbs.
- `git/load.rs` holds queries interactive views run (here, not under `tui/`, because reading git is not terminal work and plain command may need same query).
- `src/app/`: **the drill**, one `App` with `Level` stack, entered by `irepos`, `iremote`, `ibranch`, `itag`, `ilog` and `istash`.
- `src/tui/`: primitives with no view knowledge.
- `src/commands/`: one file per command. `iscan` and `istatus` stay standalone (query bar and staging area have no place in nav stack) but share shape: state struct, `on_key`, `draw`.
- `demo/`: every tape 1056x664 = 99x30 at `FontSize 15`, one size for all: `Set Height` mid-tape resizes canvas but not pty, so tape cannot change frame size; frame sized for longest scrolling report since TUI fills whatever it gets. Width decides readability: README fits pictures to ~758px, so 100 columns puts char at ~7.6px. Going narrower is side-by-side diff's call: at 100 columns it has ~50 a side, where fixture's longest lines begin needing panning. Excluded from published crate.
